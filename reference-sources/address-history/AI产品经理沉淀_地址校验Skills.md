## 一、Skills 定位

> 不是"做一个地址校验工具",而是把一个真实业务任务收敛成 AI 能稳定执行的能力模块。

| 维度 | 定义 |
|---|---|
| **服务谁** | AI 外呼电销团队 / 发货运营 / 数据清洗员(每天 1000-5000 条 ASR 采集订单) |
| **解决什么具体任务** | 把 AI 客服外呼采集到的客户口述地址,在**发货前 10 分钟内**自动校验、纠错、补全,识别"省市区错配 / ASR 同音字 / 虚构地名 / 缺门牌"等 7 类问题 |
| **最终交付什么** | ① 直接给清洗团队的 13 列业务 CSV(打面单可用)<br>② 给电销组的话术(待人工那几条怎么回拨)<br>③ 给运营老板的 MD 报告(三档分布 + 经济效益 + L0 静态预警) |

**反例** — 下面 3 种描述都太大,AI 没法稳定执行:

```
❌ 写一个地址校验 Skill
❌ 帮我清洗一下地址数据
❌ 自动找出脏数据
```

**正例** — 我们的边界:

```
✅ 输入:今天 AI 外呼 ASR 采集的客户地址 CSV(含手机号/姓名/省市区/详细地址/通话记录)
✅ 任务:用 L0 离线行政区库 + L1 高德 API + 通话记录 三路交叉,在 10 分钟内出三档分级 + 强制降级 + 自动纠错
✅ 输出:13 列业务 CSV + MD 报告 + 待人工话术 + 经济效益统计
```

任务边界清晰,所以 AI agent 拿到关键词"`<日期>地址校验`"能稳定触发、稳定执行、稳定交付。

## 二、输入信息(I/O 契约 之 输入侧)

### 用户必须提供的

| 字段 | 必需 | 容错 |
|---|---|---|
| 完整地址 | ✅ | 字段名兼容:`完整地址`/`采集新地址`/`收货地址`/`地址`/`详细地址`(7 种别名) |
| 手机号 | ✅ | 11 位明文 **或** 32 位 MD5 hex 都可,脚本自动识别 |

### 用户可选 / 强烈推荐

| 字段 | 必需 | 不给的处理 |
|---|---|---|
| 姓名 | 推荐 | 空名 / 占位词("未知客户") → 自动补 "省1字+手机后4"(如`云6516`) |
| 省 / 市 / 区/县 | 可选 | 不给就只用完整地址拼;给了就跟 L0/L1 校正结果做交叉对比(原始 3 列 + 校正 3 列双列输出) |
| 通话记录 | ⭐ 强烈推荐 | 不给就丢掉同音字纠错的关键证据(玉溪/渔溪 这种就纠不了),自动降级为字符相似度 |

### 信息不完整时的策略(产品决策)

| 缺失情况 | AI 行为 |
|---|---|
| 地址完全空 | 不假装能做,直接标 `待人工`,备注"原始地址为空,需补充" |
| 省/市/区都没传 | 用完整地址拼接,L0 解析省市区 |
| 通话记录没传 | 跳过同音字纠错层,降为字符相似度,**不假装做了** |
| MD5 手机号 + 内部 API 不通 | **静默降级**透传原 MD5,不阻塞主流程(关键:不让单点故障毁掉整批) |
| pca-code.json 缺失 | 跳过 L0,降为纯 L1 模式(并打 WARN) |
| pypinyin 没装 | 同音字层降级为纯字符相似度(并打 WARN) |

**核心原则**:**任何依赖都是软依赖,缺了能跑、不假装、不阻塞**。

## 三、执行流程(SOP)

> AI 不是"自由分析",而是按一套**6 步固定 SOP** 执行。

```
Step 1 确认输入  →  Step 2 试跑 5 条  →  Step 3 选模式跑全量
        ↓                ↓                       ↓
Step 6 处理重试 ←  Step 5 6 段汇报  ←  Step 4 读 MD 逐条核查
```

### 每步的"做什么 + 做到什么程度"

| 步 | 行动 | 完成标志 |
|---|---|---|
| 1 | Read 工具读输入前 5 行,核对字段名 | 字段映射通,没有"通话记录ID/手机号/地址"等关键字段缺失 |
| 2 | `--limit 5` 试跑 | 5 条都不报错 + CSV 13 列齐全 + 至少 1 条有效"高/中"档结果 |
| 3 | 按数据量选 mode(决策树见下表)+ 跑全量 + 必加 `--with-report` | 全量跑完 + MD 报告生成成功 |
| 4 | 读 MD 6 块:三档分布 / L0L1分布 / L0预警 / 自动纠错 / 待人工 / 抽查 | 心里有数:这批数据自动发货率多少、有几个待人工 |
| 5 | 按 6 段固定模板汇报 | 用户看到的不是技术细节,而是业务结论 |
| 6 | 处理"待重试"那几条 | 5 分钟后单独重跑,或人工补 |

### 模式决策树(产品级决策,不让 AI 乱选)

```
            数据量 < 500?
            /         \
          是            否
         /              \
       hybrid          数据量 ≥ 5000?
       (~5分钟)        /         \
                     是            否
                    /              \
              offline-first      hybrid
              (~10分钟)         (~10分钟)

(沙箱/无网络/想 7 秒出结果 → pure-l0,所有数据量通用)
```

### Agent 调用规约(关键)

不让 AI agent 自由生成命令,必须按模板:

```bash
python3 ~/.cursor/skills/dzcj-address-validate/scripts/validate.py <输入> \
        --mode <hybrid|offline-first|pure-l0|online-only> \
        --out-dir <目录> \
        --name <批次名> \
        --with-report          # ★ agent 必加,Step 4 要读 MD
```

漏了 `--with-report` agent 就没法做 Step 4,所以 SKILL.md 里**显式写"作为 agent 调用时一定要加这个 flag"**,而不是依赖 AI 自己想到。

## 四、输出结构

> 输入随便丢,但**输出必须稳定**(不是这次像 PRD 下次像聊天)。

### 给业务方:13 列业务 CSV

固定 schema,**用列名 join,不靠列序**,下游脚本不破:

| 用途 | 列 |
|---|---|
| 联系 | 手机号、手机号MD5、姓名 |
| 追溯 ASR 误差 | 原始省、原始市、原始区/县 |
| 校正后(打面单) | 省、市、区/县、详细地址 |
| 审计 | 原始地址 |
| Excel 工作流入口 | 状态(`待人工`/`待抽查`/`待重试`/空)、备注(只放原因) |

### 给上级 / 电销组:MD 报告

固定 6 段:
1. 三档分布 + 自动发货率
2. L0/L1 调用分布(节省 API 多少次)
3. L0 静态预警表(daily 漏的部分)
4. 自动纠错记录(乡镇/POI 同音字)
5. 待人工话术(直接给电销复制粘贴回拨)
6. 抽查发货段(候选地址)

### 给审计 / 后端入库(opt-in `--full-csv`):30 列完整版

含 通话记录ID / POI命中 / 经纬度 / L0状态 / 纠错记录 / 通话证据 等全字段。

### Agent 汇报给用户:6 段固定模板

```
1. 三档分布(高/中/低 各多少条、占比)
2. L0/L1 调用统计 + API 经济效益
3. L0 静态预警(行政区错配 X / 区县不在册 Y)
4. 自动纠错记录(列名单)
5. 低档"建议话术"(从 MD 摘出)
6. 产物路径(3-4 个文件全列出)
```

## 五、规则与边界(产品安全护栏)

> **AI 最大的问题不是不会说,而是太会说。**
> 这是整个 skill 最关键的部分。

### 黑名单(永远不能做)

| # | 不能做 | 后果 / 历史教训 |
|---|---|---|
| 1 | ❌ 用高德 `formatted_address` 直接当最终地址 | 门牌会被截断("X 路 18 号"丢成 "X 路")。改用 高德省市区 + 客户原始详细 拼回 |
| 2 | ❌ 删省/市/区/县 后缀 | 下游需要带后缀的标准字段 |
| 3 | ❌ 因为某字段空就判无效 | 直辖市 city 为空、省直辖县级市 district 为空都是正常的 |
| 4 | ❌ QPS / 网络失败就判终结 | 必须进"待重试",不能丢条不能假装成功 |
| 5 | ❌ POI 相似度低就盲改客户原话 | 永不修改客户原话,候选地址放进备注由人工决策 |
| 6 | ❌ 把高德反查结果直接当新地址 | "两里头镇→大集镇"可能是同音字也可能客户给错了,必须人工核 |
| 7 | ❌ 忽略 L0 预警直接给"高"档 | 历史真实事件:"韩城松市邮邮庄小区" L0 标"不在册",L1 高德硬猜到"新疆阿拉尔市"还给"高"档。**v2.9.2 hotfix 强制降级修复** |
| 8 | ❌ 在 Cursor 沙箱里跑 hybrid / online-only | 沙箱网络白名单不含高德 / 内部 API,会全失败。沙箱只能 `pure-l0 --no-decrypt-phone` |

### 强制降级触发器(任一中标即降一档)

| 触发 | 降级 |
|---|---|
| 乡镇高德反查不一致 (`township_unverified`) | 一档 |
| POI 相似度 < 50% | 一档 |
| 无门牌只到路 | 一档 |
| L0 `pca_mismatch`(行政区库错配) | **强制**一档 |
| L0 `unknown_county`(区县不在册) | **强制**一档 ★ v2.9.2 修补的关键护栏 |

### 降级、静默、报警 三个级别

| 情形 | 级别 | 行为 |
|---|---|---|
| API 单条失败 | 重试 | 内部指数退避 3 次 |
| 重试仍失败 | 待重试 | 标记进"待重试"状态,不丢条 |
| MD5 解密 API 不通 | 静默降级 | 原 MD5 透传到输出列,主流程不阻塞 |
| pca-code.json 文件缺失 | WARN | 启动 banner 打 `[WARN] L0 失效`,继续跑 |
| pypinyin 没装 | WARN | 启动 banner 打 `[WARN] 同音字纠错失效`,继续跑 |
| 输入文件不存在 | FATAL | exit 1,绝不假装 |

### "保留 + 候选" 双轨制(产品策略)

发现 L1 校正跟客户原话不一致 → **永不替换客户原话**,而是:
- 原始地址列保留客户原话
- 校正后地址列放高德结果
- 候选地址列 + 备注列 放纠错建议
- 由业务/电销人工决策

唯一例外:**拼音 ≥ 90% 的乡镇/POI 同音字**(玉溪→渔溪)→ 自动替换,因为 ASR 同音误识高频,客户原话本就大概率是错的。

## 六、质量标准(什么叫做得好)

> 不只是"能输出",而是有明确的合格 / 优秀分级。

### 合格线(每次跑完必须满足)

| 维度 | 合格标准 |
|---|---|
| 数据完整性 | 输入 N 条 → 输出 N 条(不丢条,API 失败的进"待重试") |
| Schema 一致性 | 输出 13 列全在 + 列序固定 + 列名固定 |
| 必填字段 | "手机号"列 100% 非空(MD5 也算),"详细地址"列 ≥ 95% 非空 |
| 状态归属 | 100% 行都有"状态"(`待人工`/`待抽查`/`待重试`/空)4 选 1 |
| 报告生成 | `--with-report` 时 MD 必须生成,不能因为单条异常拖死 |

### 优秀线(参考 5047 条 hybrid 实战 2026-05-28)

| 指标 | 优秀线 | 5047 实战 |
|---|---|---|
| 🟢 直接发货率 | ≥ 30% | 38% ✓ |
| 自动发货率(高+中) | ≥ 80% | 88% ✓ |
| 自动纠错条数 | ≥ 总数 × 1.5% | 106 条(2.1%)✓ |
| API 失败重试率 | < 5% | < 1% ✓ |
| 跑完总耗时 | < 1 秒/条 | 0.29 秒/条(L0 直出占比高拉低均值)✓ |

### 业务价值衡量(对比基线)

| 维度 | v1 基线(纯高德) | v2.7 同音字纠错后 | v2.10.1 当前 |
|---|---|---|---|
| 自动发货率 | 0% | 53% | **88%** |
| 自动纠错条数 | 0 | 40 | **106** |
| 比 daily(同类工具)多拦下 | — | — | **+445 条潜在错发**(0527 5047 实测) |

### 产品 KPI(给老板看)

```
- 自动发货率:88%(每天 5000 条只需人工处理 11% = 600 条)
- 节省 API 调用:offline-first 模式比 hybrid 节省 92% 高德调用
- 错发预防:相比直接发货,拦下 ~12% 潜在错发(573/5047)
- 时间成本:1 个运营本来 5000 条手动校 4 小时 → 现在 10 分钟跑完 + 30 分钟核 600 条
```

## 七、迭代方式(经验沉淀成可复用)

### 7.1 迭代节奏(8 个版本 / 2 天)

```
v2.7  (基线)    → 300 条自动发货 53%,加同音字纠错五层
v2.8  (深化)    → 乡镇层 ≥90% 拼音自动纠 + POI 同后缀护栏
v2.9.0 (架构升级) → 借鉴 daily 引入 L0 离线层 + 3 mode
v2.9.1 (对齐)   → 输出对齐 daily 8 列
v2.9.2 (hotfix) → L0 unknown_county 强制降级(防"新疆阿拉尔"误发)
v2.9.3 (优化)   → 详细地址改完整地址 + fb_district 修复 + 加 pure-l0
v2.9.4 (打磨)   → normalize_address 对齐 daily(差异 56→2 条)
v2.9.5 (精简)   → 默认只出 1 份主 CSV,其他 opt-in
v2.10.0 (4 个增量) → 原始3列 / MD5解密 / 备注拆2列 / 手机号双列
v2.10.1 (微调)  → fix_name 占位词 + 敬称识别(未知客户/李先生)
```

### 7.2 迭代心法(从踩坑里总结)

| 心法 | 触发场景 | 教训 |
|---|---|---|
| **永不修改客户原话** | v1 直接用 formatted_address 覆盖 → 门牌全丢 | 引入"保留 + 候选" 双轨制 |
| **API 失败不能丢条** | v1 QPS 限制时静默吞条 | 引入 "待重试" 状态 |
| **L0 异常必须强制降级** | v2.9.1 韩城松市被硬猜到新疆 | hotfix 把 unknown_county 加入降级条件 |
| **任何依赖都是软依赖** | v2.10.0 加 MD5 解密时担心 API 不通毁批 | 失败静默降级原值透传 |
| **占位词识别** | v2.10.0 截图发现"未知客户"原样塞面单 | 加 placeholder 集合 + 敬称正则 |
| **同事真用时才发现** | v2.10.1 同事跑命令时输错文件名 / MD5 没解密 | 改 `.command` 全自动:检测依赖 / 自动找文件 / 自动命名 |

### 7.3 沉淀成 3 个可复用模块

不止做了个 skill,而是把模块抽出来,**别的项目能复用**:

| 模块 | 路径 | 别处可用场景 |
|---|---|---|
| `pca_offline.PCAValidator` | `scripts/pca_offline.py` | 任何要做"省市区拆解 / 行政区合法性校验"的场景 |
| `phone_decoder.decrypt_phones_in_data` | `scripts/phone_decoder.py` | 任何要批量解密 MD5 → 明文的场景(支持自定义 API) |
| 同音字判定 `similarity() = max(字符%, 拼音%)` | `scripts/validate.py` | 任何 ASR 后处理 / 实体对齐场景 |

### 7.4 反馈→优化的产品节奏

```
用户跑出问题
     ↓
看截图(状态/备注列定位)
     ↓
判断:① 数据问题(回拨补采)
     ② 规则太严/太松(改阈值,如拼音 90%)
     ③ 漏掉的场景(加 placeholder / 加敬称模式 / 加 mode)
     ↓
小步快跑:1 小时改完 + 5 条测试 + 同步分发包 + 重打 zip
     ↓
更新 CHANGELOG + SKILL.md 触发约定
```

**不做的事**(同样重要):
- ❌ 不做 hardcoded 黑名单("某某客户" 这种)
- ❌ 不加复杂 ML 模型(同音字够用,加 ML 反而不可解释)
- ❌ 不做 GUI(目前命令行 + `.command` 双击对内部用户够用)
- ❌ 不堆功能(每加 1 列输出都要权衡 schema 破坏)

## 八、3 个分层交付物(沉淀的最终形态)

> 一个 skill 不只是脚本,而是 **3 层交付物**,服务不同人群。

| 层 | 交付物 | 路径 | 服务谁 | 何时用 |
|---|---|---|---|---|
| L1 工程 | Cursor Skill + 5 个脚本 | `~/.cursor/skills/dzcj-address-validate/` | 我(原作者)/ AI agent | 触发"`<日期>地址校验`"自动执行 |
| L2 分发 | 独立 zip + 全自动 `.command` | `~/Desktop/地址采集最新版.zip`(73K) | 同事 / 跨电脑 | 不会用 Cursor 也能跑(3 步:解压→拖文件→双击) |
| L3 沉淀 | 复盘文档 + 本文 | `~/Desktop/dzcj/项目复盘_v2.10.1.md` + 本文件 | 产品/老板/审计/未来的自己 | 复盘、汇报、面试、新人传承 |

## 九、给同行 AI 产品经理的总结

> 这 2 天踩出来的 7 条经验,可以用在任何 skill 设计上。

### 1. 任务边界 > 提示词长度
"写一个地址校验 Skill" 是大空话。"AI 外呼采集的地址 CSV → 10 分钟内出三档分级 + 强制降级 + 自动纠错" 才是任务。

### 2. 输入输出契约 > 自由发挥
列必须固定、列名必须固定、缺失字段有明确兜底策略。不让 AI 这次输 8 列下次输 12 列。

### 3. 步骤 > 要求
不写"请你专业",而写"先 L0 离线 → 再 L1 高德 → 最后 6 段汇报"。一套可执行 SOP,而不是几句"请你认真"。

### 4. 边界 > 聪明
最关键的是 **8 条黑名单 + 5 个强制降级触发器**。AI 知道"什么不能做"比"什么都能做"重要。

### 5. 软依赖 > 硬依赖
任何依赖(高德 API / MD5 解密 API / pca-code.json / pypinyin)失败都能降级跑,绝不让单点故障毁批。

### 6. 双轨制 > 一刀切
"保留客户原话 + 给候选"比"用 AI 结果覆盖原话"安全 10 倍。人工有兜底,不会因为 AI 错改导致错发。

### 7. 沉淀模块 > 一次性脚本
最终交付的不是 1 个脚本,而是 3 个能在别处复用的模块(pca / phone_decoder / similarity)+ 3 层交付物(skill / zip / 复盘文档)。
