# 项目 D｜AI 地址校验与人工复核工作流

性质：核单 Skill 与历史批次复盘 + LoopLab 有限规则演示 + 正式质量评测设计。业务定位为订单履约前核验，商品、价格、支付及购买意愿不在本模块证明范围。

## 1. 业务问题

地址文本“能解析”“地图能找到”不代表客户最终确认。空地址漏单、误读工作表、候选覆盖原值、错误修正和不清楚的异常状态，会直接影响后续履约。

目标是让每笔订单都能根据证据决定通过、补采、复核或重试，并记录谁作了什么决定。

## 2. 输入输出与流程

输入：订单 ID、原始地址、省市区字段、通话文本；必要时取得录音或地图候选。输出：原始值、结构化字段、候选值、差异、证据、异常原因、处理状态与人工裁决。

输入完整性 → 地址拆分 → 行政区关系 → 候选生成 → 证据核对 → 风险分流 → 人工复核/补采 → 结果留痕。

| 异常 | 正确动作 | 必须避免 |
| --- | --- | --- |
| 空地址/缺关键字段 | 保留订单并补采 | 跳过该行、自动补门牌 |
| 同名或同音地名 | 展示候选、核对上下文 | 把相似度当正确概率 |
| 原文与地图冲突 | 保留原文并转人工 | 候选直接覆盖原值 |
| 工具调用失败 | 标记依赖失败、可重试 | 显示核验通过 |
| 读错工作表/ID 异常 | 阻断或明确导入错误 | 只比较输入输出行数 |

## 3. 人机分工

程序负责字段、ID、多表读取、行政区关系、放行约束；模型可帮助理解通话上下文和组织证据；人工确认冲突、补采与最终有效地址。模型生成候选和人工批准后的结果分别记录，避免人工修正使原系统得分虚增。

## 4. 历史证据

已有复核记录：3985 条输出，工具归为可发货 2936 条（73.68%）、待人工 1014 条（25.45%）、无效 35 条（0.88%）；39 条有纠正标记。本轮引用历史复核，未重跑该批数据或重新建立真值。

这些数字能说明处理与分流规模。没有独立人工判定前，不能证明准确率、纠正正确率或净人工节省。

历史 Bad Case 材料记录：空地址曾导致少 10 条输出、多工作表默认读取首表。材料中记载已改为保留空地址、明确读取表并核对数量；本版把订单 ID 集合及逐行对应也纳入后续验收，避免仅数量相等掩盖错位。

## 5. 正式质量评测

构建分层样本，覆盖常规地址、同音、同名地区、缺门牌、改口、工具失败和表格问题。独立标注并仲裁，依据客户最终确认和业务核实；ASR 或地图结果不能直接当真值。

| 指标 | 分母与意义 |
| --- | --- |
| 错误放行率 | 被评审的自动通过记录中，错误或不应通过的比例 |
| 问题拦截召回 | 应复核记录中，被系统正确拦截的比例 |
| 纠错精确率 | 被系统修改记录中，修改正确的比例 |
| 正确地址误改率 | 原本正确的记录中，被系统改错的比例 |
| 订单守恒 | 输入与输出的 ID 集合、数量与逐条映射一致性 |
| 人工负载 | 每百单复核分钟数、补采量与返工量 |

整体误差控制与人工负载共同决定自动化范围。无真值的导入数据只报告处理分布，不显示准确率。

## 6. 可运行证据与后续

LoopLab 提供 24 条虚构地址、独立示例真值、v1/v2 有限规则、人工裁决和导出。仅覆盖有限区县；未接真实地图、ASR 或生产核单脚本，页面通过不代表真实地址可寄送。历史 3985 条与这 24 条不合并计算。

下一步补独立地址真值和真实人工耗时，再对比规则基线与模型辅助；若迁移汽车礼品寄送，重新核对地址字段与交付要求。

来源：S03、S04、S09。


## 7. V2 复跑：自动化覆盖与错误放行的取舍

本轮复跑既有 24 条合成挑战案例，未修改原核验引擎：

| 指标 | 演示规则 v1 | 演示规则 v2 |
| --- | --- | --- |
| 自动通过 | 20/24（83.33%） | 11/24（45.83%） |
| 自动通过中的错误 | 9/20 | 0/11 |
| 应拦截问题被拦截 | 4/13 | 13/13 |

例如 DEMO-012：地址含“西胡区”，通话没有确认依据。v1 替换为“西湖区”后通过；v2 提供候选并转人工。这展示收紧自动化范围以降低错误，而非以通过率最大化作为唯一目标。

Gold 在推理输入之外，由合成案例预置，不代表真实独立标注；v1/v2 是演示规则对比，不是生产历史版本。0/11 不能外推为实际地址零风险。结果文件保留了 Wilson 区间计算，仅用于说明小分母的不确定性，不能把合成样本当作真实随机抽样总体。
