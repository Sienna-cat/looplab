# Bad Case 管理与迭代机制

> 工具上线后,真正决定它好不好用的是"**坏案例能不能被快速收集、定位、修掉、并且不复发**"。本篇定义这套闭环。台账数据见 [`bad_case_log.csv`（原始表未随公开副本提供）](原始数据说明.md)。

---

## 一、闭环总览

```
收集 ──→ 分类 ──→ 分级 ──→ 修复 ──→ 回归 ──→ 关闭 + 沉淀
 ↑                                                    │
 └────────────  发货异常 / 同事反馈持续回流  ────────────┘
```

一句话原则:**每个 bad case 都要落台账,每个修复都要在真实批次回归,验证"修好了 + 没改坏别的"。**

---

## 二、① 收集(谁、怎么报)

任何人发现"工具判错/改错/补错/丢行"都可登记,**一行一个**,填进 [`bad_case_log.csv`（原始表未随公开副本提供）](原始数据说明.md)。模板字段:

| 字段 | 说明 | 例 |
|---|---|---|
| `日期` | 发现日期 | 2026-06-03 |
| `来源` | 谁/哪个环节发现 | 发货退件 / 坐席 / 抽查 / 同事试用反馈 |
| `原始地址` | 采集进来的原文 | 河南省开封市未提及东郊十一化建生活区 |
| `工具输出` | 校验后的地址 + 状态 + 备注 | …未提及东郊… / 待人工 |
| `期望结果` | 正确应该是什么 | 去掉"未提及",东郊十一化建生活区 |
| `类型` | 见第三节分类 | 占位词残留 |
| `影响面` | 大概多少行受影响 | 偶发 / 约5% / 10条/批 / 普遍 |

> **低门槛**:报的人只要填前 5 列,`类型/影响面`由清洗同事补。

---

## 三、② 分类(决定改哪里)

| 类型 | 典型现象 | 一般修复落点 |
|---|---|---|
| **解析/分词** | 区县被截断、详细地址被吞、**整行被丢、读错 sheet** | `batch_verify.py` 解析逻辑 / `fused_validate.py` 读取与列识别 |
| **同音错字** | 音近字没纠正 / 纠错过头 | 拼音字典 + `phon_score` 阈值 |
| **区县归属** | 省与区县冲突误判 / 漏判 | 行政区划库 + 冲突判定 |
| **占位词残留** | "未提及/未知/不详"进了地址 | 占位词过滤名单 |
| **门牌完整度** | 该可发货判了待人工(或反之) | `_has_door_detail` 判定 |
| **地图核验** | POI 误命中 / 乡镇被臆造 | 相似度阈值 + `has_detail` 护栏 |
| **手机号解密** | MD5 没解出 / 解错 | 解密接口 / 大小写映射 |
| **姓名补全** | 姓没补 / 补错 | `fix_name` |

---

## 四、③ 分级(决定先修谁)

优先级 = **影响面 × 频次**:

| 级别 | 标准 | 处理时效 |
|---|---|---|
| **P0** | 普遍 / 导致错发货 / 把对的改错(批量)/ **静默丢行** | 当天热修 |
| **P1** | 约 1–5% 行受影响,或高频单类型,或**潜在全表错位** | 本周内 |
| **P2** | 偶发 / 个例 / 边角 | 攒批,下个迭代一起修 |

> 判错(把脏判成可发货)比漏判(把能发的判成待人工)更严重——**前者会错发,后者只是多花人工**。
> **静默丢行**尤其危险:数据凭空消失且无提示,默认按 P0 处理,并要求脚本打印"保留/跳过条数"留痕。

---

## 五、④ 修复(改对地方,不打补丁)

修复原则:

1. **离线优先**:能用规则/字典解决的不依赖联网。
2. **不确定不改**:纠错/补全只在高置信度(阈值达标)时动手,宁可留"待人工"也不臆造。
3. **加护栏而非加规则**:很多 bad case 是"过度处理",修复是**加边界条件**(如门牌不全不做 POI、行政区划名不臆造乡镇),不是堆新规则。
4. **不许静默丢数据**:任何"跳过/过滤"都要么保留并标记,要么打印计数;**绝不让行无声消失**。
5. **改在引擎,不改在输出**:在 `batch_verify.py`/`fused_validate.py` 的判定处修,不要在结果表上事后打补丁。

---

## 六、⑤ 回归(必须量化前后)

每个修复合入前,在**真实批次**上验证两件事:

- **修好了**:目标 bad case 及同类不再复现(列出具体案例条数,前 X 条 → 后 0 条)。
- **没改坏**:整批 3 档分布(可发货/待人工/无效)与上一版对比无异常漂移;**行数对齐**(输出行数 = 读入行数);抽查 `[已纠]` 行仍正确。

> 把回归批次和前后数字记到台账的 `回归验证` 列,留痕。

## 七、⑥ 已修复台账(沉淀,防复发)

下列为已闭环的 bad case,后续若复现直接对照定位(完整见 [`bad_case_log.csv`（原始表未随公开副本提供）](原始数据说明.md)):

| 案例 | 现象 | 修复 | 状态 |
|---|---|---|---|
| 管城区→城区 | 有效区县被窗口扫描截断,误报省区县冲突 | `detect_county_in_addr` 加左边界保护 + 原始有效区县兜底保留 | ✅ 已回归(32 例) |
| 未提及残留 | "未提及"被当区县并入详细地址 | `batch_verify` 占位词名单(精确+子串)过滤 | ✅ 已验证无残留 |
| 钱塘区→河庄街道 | 纯行政区划地址被 POI/逆地理臆造出乡镇 | POI 回退 + 乡镇补全均加 `has_detail` 护栏 | ✅ 已修复 |
| POI 误命中 | 地图回退命中不相关 POI | `_sim`/`phon_score` 相似度阈值(0.40)+ 标注"POI疑似误命中" | ✅ 已上线 |
| 状态语义不清 | 缺市区与省区县冲突混在"待人工" | 重构为 3 档:冲突→无效、缺/无门牌→待人工、齐全→可发货;`[已纠]`下沉到备注 | ✅ 已上线 |
| **静默丢 10 行**(2026-06) | 被处理表里「地址」列为空的行,被 `if not addr: continue` 丢弃,输出比输入少 10 条且无提示 | `fused_validate` 解析循环:去掉"地址空即跳过",空地址用 `省+市+区县` 兜底并强标"待人工"、备注注明;只跳"整行全空";并打印"保留/跳过条数" | ✅ 已修复(重跑输出=读入 3998,行数对齐) |
| **多 sheet 读错表**(2026-06) | 同一 xlsx 有多张 sheet,`read_sheet` 固定读第一个(`sheet_names[0]`),可能不是用户在界面看的活动表(schema/行数都不同) | `fused_validate` 默认改读**活动表**;新增 `--sheet 表名` 可指定;启动打印"实际读取的表名 + 行数 + 表头",多表时额外告警 | ✅ 已修复(误读可凭启动日志发现并用 `--sheet` 纠正) |
